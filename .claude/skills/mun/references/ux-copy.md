# UX copy rules

Words exist to make the interface easier to understand and use.

## Principles
- Write from the user's side, in their words, not the system's: "Manage notifications", not "Webhook config".
- Be specific over clever. Plain verbs, active voice, sentence case.
- One job per element. Cut filler ("simply", "just", "please note").
- Keep one name per action across the flow: a "Publish" button leads to a "Published" toast.
- Match the brand's tone, but clarity comes first.

## Patterns
| Element | Do | Avoid |
|---|---|---|
| Button / CTA | Say the result: "Start free lesson", "Save changes" | "Submit", "Click here", "Learn more" everywhere |
| Headline | The user's benefit or the subject, concretely | Vague hype ("Unlock your potential") |
| Error | What happened + how to fix it: "Card number is too short. Check the 16 digits." | "Oops! Something went wrong", apologies, error codes alone |
| Empty state | What this space is for + the first action: "No lessons saved yet. Tap ♡ on any lesson to keep it here." | "Nothing here" |
| Confirmation | Name what happened: "Booking confirmed for Tue 3 pm" | "Success!" |
| Destructive action | Name the consequence: "Delete 3 files? This can't be undone." | "Are you sure?" |
| Form label | Short noun: "Email" | Questions or sentences as labels |
| Helper text | Constraints before the user fails: "At least 8 characters" | Only telling them after an error |

## Honesty
Never invent testimonials, ratings, user counts, awards, or press logos as if they were real. Use clearly marked placeholders such as `[Testimonial from a real student]`.
